## 错误说明段

### Bug #7 (reproduced 2026-07-25 05:06 UTC, 2026-07-25 05:13 UTC after restart): connection drops + pool cold-start slow
- **Repro (mid-session)**: 调 5-10 个连续 tool call 后,下一调返回 "数据库未连接" + `get_connection_status` 返回 `connected:false`。首次重连必失败(返回 "PostgreSQL 连接失败:" 空错误),第二次重连常成功。
- **Repro (post-restart, 2026-07-25 05:13)**: Claude Code 重启后第一次 `connect_database` 失败 4 次(返回空错误),即使 PG 容器已 `pg_isready OK` + `accepting connections`。**5 次重试 + 8s sleep 后**才连上。
- **Likely cause**: `pg.Pool` 冷启动 race + idleTimeout/keepAlive 边界 + MCP server 缓存 first connection 失败 + `connect_database` handler 无 retry。
- **Fix 候选** (deferred to v3.2.5):
  - (a) `connect_database` handler 加 auto-retry (exponential backoff, 500ms/1s/2s, max 3 retries)
  - (b) `application_name` + `keepAliveInitialDelay` 调小 + pool `min` 提高到 2
  - (c) `databaseService.executeQuery` 加 `withRetry(2)` 包装
- **Severity**: HIGH — 完全阻断多 batch L2 测试,每次 Claude Code 重启都触发

### Bug #8 (Claude Code MCP client limitation, NOT FIXABLE FROM SERVER SIDE)
- **Observation**: After `use_tool_group({group:'profiles', action:'activate'})`, MCP server sends `notifications/tools/list_changed` (per v3.2.1 fix). **Claude Code does NOT refresh its cached tool list**. As a result, none of the 25 lazy group tools (save_template, lint_sql, explain_query_with_advice, etc.) are accessible to the model even after activation.
- **Severity**: HIGH — defeats entire purpose of lazy-loading for Claude Code
- **Workaround**: Disable `DB_LAZY_LOAD_ENABLED` (set default false in `.mcp.json`) — then all 43 tools show in initial `tools/list`
- **Long-term fix**: depend on Claude Code MCP client to refresh tool list; OR change `lazyLoadEnabled` default + remove `tools.listChanged: true` capability
