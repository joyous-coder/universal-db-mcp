# Universal DB MCP — v2.19 Multi-Profile 设计文档

**日期**: 2026-07-24
**作者**: brainstorming 会话
**状态**: 待用户审阅
**范围**: v2.19 P3 — Profile 加密 (SQLCipher) + 跨 profile 模板/历史

---

## 1. 背景与目标

v2.18 引入 ProfileManager，但 profiles.db 里 profile 的 `config_json` 字段含明文密码（README 已强提示 `.gitignore` 临时方案）。同时 v2.17 的 templates / history 没有 profile 维度，跨 profile 模板/历史查询不可用。

v2.19 目标:
1. **Profile 加密** — `profiles.db` 用 SQLCipher 整 db 加密，key 通过 `DB_PROFILE_ENCRYPTION_KEY` env 提供
2. **跨 profile 模板** — templates 表加 `profile_name` 列（NULL = 全局模板，向后兼容）
3. **跨 profile 历史** — history 表加 `profile_name` 列 + 索引，query 支持 `group_by='profile'` 聚合

**配套不做的（推到 v2.20+）**:
- Key rotation（多 key）
- Templates/history SQLCipher 加密（占位 env var）
- 跨 profile JOIN / 事务 (XA)
- 读副本延迟检测

**配套后续任务**:
- 跑通后重命名 `docs/multi-db.md` 为 `docs/multi-profile.md`（覆盖 v2.18+v2.19）

---

## 2. 非目标 (Non-goals)

- 不破坏现有 API 向后兼容（TemplateStore / HistoryStore 新增字段 nullable, 不破坏老调用）
- 不做 key rotation（v2.20+ 再做）
- 不做 OS keyring 集成
- 不做模板版本控制
- 不做 SQLCipher 加密 templates/history（仅占位 env var）
- 不做 profile import/export (YAML/JSON)
- 不做跨 profile JOIN / 事务

## 3. 架构总览

```
┌─────────────────────────────────────────────────────────────┐
│                  Stores (Profile / Template / History)        │
│  constructor(dbPath, { cipherKey?: string })                 │
│  init() → 选 backend                                          │
└─────────┬─────────────────────────────┬──────────────────────┘
          │ key 未提供                  │ key 提供
          ▼                             ▼
┌──────────────────┐         ┌─────────────────────────────────┐
│ v2.16 multi-     │         │ EncryptedSqliteBackend          │
│ backend (node:   │         │   - NativeBackend (v2.16)       │
│ sqlite / better) │         │   - CipherBackend (SQLCipher)   │
│                  │         │     uses better-sqlite3-multi-   │
│                  │         │     ciphers + PRAGMA key        │
└──────────────────┘         └─────────────────────────────────┘
```

**关键决策**:
1. ProfileStore 单独走 SQLCipher；templates/history 用 native (按 profileName 字段 + 索引)
2. Key 缺失时不报错 — fallback v2.18 行为（明文存）；warn 一次
3. v2.18 的 profiles.db 不迁移（旧明文 db 仍可读，新 save 用 SQLCipher 后老 db 不能读 — 用户需手动 save_profile 重建）
4. SQLCipher 库用 `better-sqlite3-multiple-ciphers` (~5MB), 装在 `optionalDependencies`

## 4. 核心组件 API

```typescript
// 抽象 backend（v2.19 新增）
export interface EncryptedSqliteBackend {
  name: 'native' | 'cipher';
  open(dbPath: string, options: { readonly?: boolean; cipherKey?: string }): Promise<SQLiteConnection>;
}

// 实现
export class NativeSqliteBackend implements EncryptedSqliteBackend {
  name = 'native' as const;
  async open(dbPath, options): Promise<SQLiteConnection>;
}

export class CipherSqliteBackend implements EncryptedSqliteBackend {
  name = 'cipher' as const;
  async open(dbPath, options): Promise<SQLiteConnection>;  // PRAGMA key = options.cipherKey
}

// ProfileStore 构造签名变化
export class ProfileStore {
  constructor(
    public readonly dbPath: string,
    public readonly options?: { cipherKey?: string }
  );
}

// 扩展 schema（v2.19 加列）
// templates 表:
ALTER TABLE templates ADD COLUMN profile_name TEXT;  // nullable

// history 表:
ALTER TABLE query_history ADD COLUMN profile_name TEXT;  // nullable
CREATE INDEX idx_history_profile ON query_history(profile_name);

export class TemplateStore {
  constructor(dbPath: string);
  async list(filter?: { tag?: string; profileName?: string | null }): Promise<Template[]>;
  // filter.profileName === null → 只查全局 (profileName IS NULL)
  // filter.profileName === 'p' → 只查该 profile
  // filter.profileName === undefined → 全部 (向后兼容)
}

export class HistoryStore {
  constructor(dbPath, opts: { ttlDays; maxRows; profileName?: string });
  async record(input: QueryHistoryInput): Promise<void>;
  async query(filter: HistoryFilter): Promise<QueryHistoryEntry[]>;
  // filter.profileName + groupBy: 'profile' → 返回 { profileName, count, errors, avg_ms }[]
}

export class QueryAnalyzer {
  setProfileProvider(fn: () => string | null): void;
  // recordQuery(input) 自动加 profileName = fn()
}

export class DatabaseService {
  setQueryAnalyzer(qa: QueryAnalyzer | null): void;
}
```

## 5. 集成点

| # | 位置 | 调用 | 备注 |
|---|------|------|------|
| 1 | `src/utils/encrypted-sqlite.ts` (新) | EncryptedSqliteBackend 接口 + 2 实现 | v2.19 新增 |

| 5 | `src/core/query-analyzer.ts` | `setProfileProvider()` + `recordQuery(input)` 加 profileName | |
| 6 | `src/core/database-service.ts` | `executeQuery` 等埋点处传 active profile | 已有 setQueryAnalyzer，扩展 |

| 9 | `src/http/routes/query-experience.ts` | `/api/query-history` / `/api/templates` 加 profileName query 参数 | |
| 10 | `package.json` | `optionalDependencies` 加 `better-sqlite3-multiple-ciphers` | ~5MB，可选 |

**关键流程 — 跨 profile 历史记录**:
```
LLM 调 use_profile("prod-mysql")
  ↓ MCP server activeProfile = "prod-mysql"
LLM 调 execute_query("SELECT * FROM orders")
  ↓ DatabaseService.executeQuery 调 queryAnalyzer.recordQuery
    ↓ recordQuery 从 queryAnalyzer.profileProvider() 拿 activeProfile
    ↓ history.db INSERT profile_name="prod-mysql"
LLM 调 get_query_history({profileName: "prod-mysql"})
  ↓ HistoryStore.query() 过滤 profile_name="prod-mysql"
```

**关键流程 — Profile 加密**:
```
启动时 env DB_PROFILE_ENCRYPTION_KEY="..."
  ↓ ProfileStore 构造接收 cipherKey
  ↓ init() 检测到 key → 用 CipherSqliteBackend
  ↓ backend.open() 跑 PRAGMA key='...' → SQLCipher 透明加密整个 profiles.db
```

## 6. 配置与环境变量

| Env var | 默认 | 作用 |
|---------|------|------|
| `DB_PROFILE_ENCRYPTION_KEY` | (空) | SQLCipher 加密 key；空时 ProfileStore fallback 明文 |
| `DB_TEMPLATES_DB_KEY` | (空) | templates.db SQLCipher key（v2.19 暂不启用，仅占位） |
| `DB_HISTORY_DB_KEY` | (空) | history.db SQLCipher key（v2.19 暂不启用） |

**警告文案 (启动时输出一次)**:
```
[profile] WARNING: DB_PROFILE_ENCRYPTION_KEY is empty — profiles.db stored as plaintext.
         Set DB_PROFILE_ENCRYPTION_KEY to encrypt profile credentials at rest.
```

**Key 缺失/错误处理**:
- **缺失**: fallback native，warn 一次
- **错误**: 抛清晰错误 `"failed to decrypt profiles.db — check DB_PROFILE_ENCRYPTION_KEY"`，不 silent fall back
- **启动**: 尝试打开 profiles.db 验证 key；fail 不阻断 startup 但 warn

## 7. 数据库迁移

**`profiles.db`** (v2.18 → v2.19):
- v2.18: profiles 表（明文）
- v2.19: ProfileStore 检测 key:
  - key 未设置 → NativeSqliteBackend（v2.18 兼容）
  - key 设置 + db 已加密 → CipherSqliteBackend 读
  - key 设置 + db 未加密 → warn + 走 CipherBackend 写新文件

**`templates.db`** (v2.17 → v2.19):
```sql
ALTER TABLE templates ADD COLUMN profile_name TEXT;  -- 幂等
CREATE INDEX IF NOT EXISTS idx_templates_profile ON templates(profile_name);
```
老模板自动 profile_name=NULL (= 全局模板)

**`history.db`** (v2.17 → v2.19):
```sql
ALTER TABLE query_history ADD COLUMN profile_name TEXT;  -- 幂等
CREATE INDEX IF NOT EXISTS idx_history_profile ON query_history(profile_name);
```

## 9. 风险与权衡

| 风险 | 等级 | 缓解 |
|------|------|------|
| 升级 v2.18 → v2.19 老 profiles.db 是明文、新版本用 SQLCipher | 高 | 检测 cipher_version, fallback native; README 强提示 |
| 输错 key 导致 db 损坏 | 中 | 抛清晰错误，不 silent fall back |
| SQLCipher 库装不上 | 中 | optionalDependencies，降级明文 + warn |
| Templates/History 加 profile_name 列后老 db 不兼容 | 低 | ALTER TABLE ADD COLUMN 幂等 |
| active profile 注入 recordQuery 时丢失 | 低 | server 端 activeProfile, null 时不传 |
| group_by='profile' 聚合查询慢 | 低 | idx_history_profile 索引 |
| DB_PROFILE_ENCRYPTION_KEY 误传到 log | 中 | 只输出 key length, 不输出内容 |
| SQLCipher 与 v2.16 node:sqlite 冲突 | 低 | 仅 ProfileStore 用 cipher, 其他用 native |
| 加列后 templates.db / history.db 文件锁 | 低 | ALTER TABLE ADD COLUMN 是轻量操作 |

**未做 (YAGNI)**:
- Key rotation — v2.20+
- Templates/history SQLCipher — 占位 env var
- Profile import/export
- 模板 version 控制
- Key 派生 (PBKDF2)
- OS keyring 集成

**回退方案**:
- `DB_PROFILE_ENCRYPTION_KEY` 留空 → fallback v2.18 明文
- `better-sqlite3-multiple-ciphers` 装不上 → fallback native + warn
- 启动期 ProfileStore 错误 → service 仍启动，只 warn
