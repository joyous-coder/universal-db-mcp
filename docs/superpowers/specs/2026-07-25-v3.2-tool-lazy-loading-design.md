# Universal DB MCP — v3.2 Tool Lazy-Loading 设计文档

**日期**: 2026-07-25
**作者**: brainstorming 会话
**状态**: ✅ 用户批准所有 7 节
**范围**: v3.2 P3 — MCP tool 懒加载（4 group + info-lazy）+ 补全 11 个未注册 MCP tool + 5 个 profile lifecycle tool

---

## 1. 背景与目标

v3.0-v3.1 完成了 Data Governance 和 Index Advisor，MCP tool 数量从 v2.14 的 6 个膨胀到 22 always-on + 4 conditional = **26 个**，description + schema 加起来约 **1,750 tokens**。

每次 Claude Desktop 启动 session，所有 26 个 tool 的 definition 都被加载到 LLM 上下文。实际场景中：

- 简单查询会话只用 5 个 tool（connect/execute_query/get_schema/clear_cache/disconnect）
- 复杂 devops 会话可能用 8-12 个
- 但**所有 session 都付全部 26 个的 tokens**

**目标**：通过**两层懒加载**降低 default session tokens 60%：

1. **Group 懒加载**（核心）：22 个 tool 拆 4 group，default session 只挂 core（12 tool）+ meta（2 tool）= **14 tool**，节省 ~700 tokens
2. **Info-lazy**（边缘）：`generate_sample_data` 巨型 schema（~900 chars）拆"轻 schema + 全 schema via meta-tool"，再省 ~600 tokens

**配套补全**：
- 11 个 v2.20/v3.0/v3.1 已实现但未注册的 MCP tool
- 5 个 profile lifecycle tool（HTTP-only 转 MCP）

---

## 2. 非目标 (Non-goals)

- 不破坏 v2.14-v3.1 API（tool name 全部保留；description 加 `[group: xxx]` hint）
- 不引入新必需 npm 依赖
- 不引入 group 持久化（每次 session 临时，已与用户确认）
- 不做 group 自动激活（纯手动，LLM 看到 `[group: xxx]` 后显式 `use_tool_group`，已确认 YAGNI）
- 不为 HTTP REST API 加 group 机制（已确认 HTTP 完全独立）
- 不暴露每个 group 单独的 env（一个 `DB_LAZY_LOAD_ENABLED` + 一个 `DB_LAZY_DEFAULT_GROUP` 足够）
- 不做 schema 自动验证（info-lazy 仅提供 `use_tool_schema` 拉取完整定义 + error hint）
- 不做 UI / dashboard（仅 MCP tool 层）

---

## 3. 架构总览

```
┌────────────────────────────────────────────────────────────────┐
│ DatabaseMCPServer                                               │
│                                                                  │
│  ┌──────────────────────────────────────────────────────┐      │
│  │ ToolRegistry  (new)                                   │      │
│  │   ├─ coreGroup (12 tools, always-on)                  │      │
│  │   ├─ lazy groups (4):                                 │      │
│  │   │   ├─ 'query-experience'  (9 tools)                │      │
│  │   │   ├─ 'profiles'          (11 tools)               │      │
│  │   │   ├─ 'data-governance'   (5 tools)                │      │
│  │   │   └─ 'index-advisor'     (3 tools)                │      │
│  │   ├─ infoLazyRegistry (1: generate_sample_data)       │      │
│  │   └─ sessionGroups: Map<sessionId, Set<Group>>        │      │
│  └──────────────────────────────────────────────────────┘      │
│           │                                                      │
│           ▼                                                      │
│  ListToolsRequest → coreGroup + active groups + infoLazy       │
│  CallToolRequest  → dispatch via ToolRegistry.callTool         │
└────────────────────────────────────────────────────────────────┘
                            │
        ┌───────────────────┼───────────────────┐
        ▼                   ▼                   ▼
   stdio              MCP SSE/Streamable    REST API
   sessionId=         HTTP sessionId=        (not affected)
   'stdio-default'    MCP session id         v3.1 behavior
```

### 3.1 三种接入方式的关系

| 接入方式 | 协议 | group 机制 |
|---|---|---|
| **stdio** | MCP | ✅ 走 group（sessionId 固定 = `'stdio-default'`）|
| **SSE** `/sse` | MCP over HTTP | ✅ 走 group（sessionId = MCP SDK session id）|
| **Streamable HTTP** `/mcp` | MCP over HTTP | ✅ 走 group（sessionId = MCP SDK session id）|
| **REST API** `/api/...` | 普通 REST | ❌ 不走（保持 v3.1 行为）|

## 4. 核心 API

### 4.1 ToolRegistry

```typescript
// src/mcp/tool-registry.ts (新)

export type ToolGroup = 'query-experience' | 'profiles' | 'data-governance' | 'index-advisor';

export interface ToolDefinition {
  name: string;
  description: string;          // 包含 [group: xxx] hint (lazy) 或完整描述 (core)
  inputSchema: JSONSchema;       // core: full; lazy: full (in registry, 仅当 group active 时返回); info-lazy: 轻
  /** v3.2: which group this tool belongs to. null/undefined = core. */
  group?: ToolGroup | null;
  /** v3.2: if true, inputSchema in ListToolsRequest 是轻量版，全版通过 use_tool_schema 拿 */
  infoLazy?: boolean;
  /** v3.2: handler builder 调用器 */
  call: (args: any) => Promise<any>;
}

export interface RegistryConfig {
  queryAnalyzer: QueryAnalyzer;
  profileManager: ProfileManager;
  profileStore: ProfileStore;
  /** 是否启用懒加载（DB_LAZY_LOAD_ENABLED）。false 时 listActiveTools 返回全部 */
  lazyLoadEnabled: boolean;
  /** 启动预激活的 group 列表（DB_LAZY_DEFAULT_GROUP 解析） */
  defaultActiveGroups: ToolGroup[];
}

export class ToolRegistry {
  constructor(private cfg: RegistryConfig) { /* ... */ }

  /** 给定 session 列出当前可用的 tool（含 meta） */
  listActiveTools(sessionId: string): ToolDefinition[];

  /** 激活 group */
  activateGroup(sessionId: string, group: ToolGroup): {
    alreadyActive: boolean;
    activeGroups: ToolGroup[];
    newlyAvailable: Array<{ name: string; description: string }>;
  };

  /** 取 info-lazy 工具的完整 schema */
  getFullSchema(toolName: string): JSONSchema | null;

  /** 检查 tool 是否在当前 session active */
  isToolActive(sessionId: string, name: string): boolean;

  /** 调度一个 tool call */
  callTool(name: string, args: any): Promise<any>;

  /** 验证 info-lazy 工具的 args（轻 schema 校验失败时给 hint） */
  validateArgs(toolName: string, args: any): { ok: boolean; hint?: string };
}
```

### 4.2 Meta-tool 定义

#### 4.2.1 `use_tool_group`

```typescript
{
  name: 'use_tool_group',
  description: '激活一个 tool group 以解锁其下的工具。已激活的 group 重复调用是 no-op。',
  inputSchema: {
    type: 'object',
    properties: {
      name: {
        type: 'string',
        enum: ['query-experience', 'profiles', 'data-governance', 'index-advisor'],
        description: 'group 名',
      },
    },
    required: ['name'],
  },
  // 返回
  // { activated, alreadyActive, activeGroups, newlyAvailable[] }
}
```

#### 4.2.2 `use_tool_schema`

```typescript
{
  name: 'use_tool_schema',
  description: '加载 info-lazy 工具的完整 schema。仅 generate_sample_data 是 info-lazy。',
  inputSchema: {
    type: 'object',
    properties: {
      name: { type: 'string', enum: ['generate_sample_data'] },
    },
    required: ['name'],
  },
  // 返回 { name, schema: JSONSchema }
}
```

### 4.3 错误处理

      group: 'data-governance',

### 5.1 Tool Description 规范

#### A. core（always-on）— 完整描述

```
"执行 SQL 查询或数据库命令。支持 SELECT/INSERT/UPDATE/DELETE..."
```

#### B. lazy group tool — 极简 + group hint

格式：`<10-15 字动作>。[<1 行关键点>]。[group: <name>]`

**实际例子**（每条 ~50-70 chars）：

| 工具 | 描述 |
|---|---|
| `compare_profile_schemas` | `对比两个 profile 的 schema 差异 (added/removed/modified)。[group: data-governance]` |
| `export_backup` | `导出 profile 为 SQL dump (CREATE TABLE + INSERT)。[group: data-governance]` |
| `audit_log` | `查询 SQL 审计日志 (actor/severity/profile 过滤)。[group: data-governance]` |
| `get_pii_config` | `读取 PII 脱敏配置 (pii.config.json)。[group: data-governance]` |
| `set_pii_config` | `运行时更新 PII 脱敏规则 (无需重启)。[group: data-governance]` |
| `explain_query_with_advice` | `EXPLAIN + 索引建议 (CREATE INDEX SQL)。[group: index-advisor]` |
| `compare_query_plans` | `对比两个 PlanHistory 同 queryHash 的 plan。[group: index-advisor]` |
| `list_query_plans` | `最近 plan 快照，按 queryHash 过滤。[group: index-advisor]` |
| `export_profiles` | `导出 profile 为 YAML/JSON (可 redact 密码)。[group: profiles]` |
| `import_profiles` | `导入 profile YAML/JSON (merge/replace + dryRun)。[group: profiles]` |
| `get_profile` | `读单个 profile 配置。[group: profiles]` |
| `delete_profile` | `删除一个 profile。[group: profiles]` |
| `enable_profile` | `启用 profile（写入 enabled 标志）。[group: profiles]` |
| `disable_profile` | `禁用 profile（自动 unload）。[group: profiles]` |
| `disconnect_profile` | `断开指定 profile（不删配置）。[group: profiles]` |

> 同样 pattern 套用到 `query-experience` / `profiles` 已有工具（`explain_query` 等）。

#### C. info-lazy（`generate_sample_data`）— 短描述 + schema hint

```
"按表结构生成 + 插入样例数据。需要 insert+batch 权限。
 详细参数用 use_tool_schema('generate_sample_data') 拿。"
```

## 9. 风险与权衡

| 风险 | 等级 | 缓解 |
|---|---|---|
| LLM 不知道新 meta-tool 存在 | 中 | `use_tool_group`/`use_tool_schema` 在 core always-on；description 写明用法 |
| Lazy tool 描述太短导致 LLM 不知道怎么调 | 低 | 统一格式 `<动作>。[<1行要点>]。[group: <name>]` |
| 多 session 共享 state 串扰 | 低 | ToolRegistry.sessionGroups 用 Map<sessionId, Set> 隔离 |
| HTTP mode 每次 session 重新激活 | 低 | 已确认（Q1 临时状态）|
| 5 个 lifecycle tool ProfileManager.setEnabled 路径未跑通 | 中 | unit test 必须覆盖联动 |
| generate_sample_data 拆轻 schema 后 LLM 不会用 | 低 | use_tool_schema 返回 examples 列表；轻 schema 含 type enum + 必填字段 |
| mcp-server.ts 重构回归风险 | 中 | 保留所有 tool name + description 不变；只加 lazy 机制 |
| Claude Desktop 重启后 group 状态丢失 | 低 | 已确认（Q1）；用户接受每次 session 重激活 |

**未做（YAGNI）**：
- Group 持久化（每次 session 临时）
- 自动激活（纯手动）
- 持久化激活组（基于 SQLite profiles.db）
- 每个 group 单独 env

**回退方案**：
- `DB_LAZY_LOAD_ENABLED=false` → ListTools 返回全部 43 tool，行为完全等同 v3.1 + 11 个新 tool

## 10. 未来任务（不在本 spec）

- **v3.3**: 按需自动激活（LLM 调懒加载 tool 时 server 自动激活对应 group）
- **v3.3**: `use_tool_schema` 扩展到所有 schema > 500 chars 的工具
- **v3.3**: 持久化激活组（基于 SQLite `profiles.db`）
- **v3.4**: Group 内部细粒度 sub-group（如 `data-governance` 拆 `audit` / `pii` / `backup`）
- **v3.5**: 跨 profile 事务（v2.18 永久不做 —— 移出 backlog）
