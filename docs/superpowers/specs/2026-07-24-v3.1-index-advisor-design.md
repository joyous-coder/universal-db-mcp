**日期**: 2026-07-24
**作者**: brainstorming 会话
**状态**: ✅ 用户批准所有 10 节
**范围**: v3.1 P3 — Index Advisor + Plan Diff + Plan History

---

## 1. 背景与目标

v2.17 (Explain Plan)、v3.0 (Schema diff + Backup + Audit + PII) 已上线。但 LLM 写 SQL 后只能看到 EXPLAIN plan，并不能：
- 自动建议 "加个索引能优化"
- 对同一查询两次 EXPLAIN 做差异比较（before/after 优化）
- 跨时间跟踪 query plan 变化（"上周这个查询还好好的，现在变慢了"）

这些都是 v2.17 §11 + v2.19 §11 + v3.0 §11 deferred 项目，本 spec 兑现。

**4 个能力**:
1. **`IndexAdvisor.analyze(profileName, sql)`** — parse EXPLAIN plan，检测 sequential scans / large row estimates / non-indexed joins，建议 `CREATE INDEX` SQL
2. **`PlanDiff.compare(planA, planB)`** — 结构化对比两次 EXPLAIN plan，标记 cost + scan type + estimated rows 变化
3. **`PlanHistory` storage** — 新独立 `plan_history.db` SQLite 文件，存储 `sql_template` / EXPLAIN JSON / `query_hash` / captured_at
4. **MCP/HTTP 暴露** — `explain_query_with_advice` / `compare_query_plans` / `list_query_plans` 三个工具

**配套不做的（推到 v3.2+）**:
- 跨 profile plan 对比（plan diff 只在单 profile 同一 query hash 间比较）
- mongodb aggregation pipeline 的 cursorStageAnalysis
- clickhouse EXPLAIN AST 详细解析
- LLM-driven 自动 apply CREATE INDEX（始终需 human review）
- redis / 缓存 DB 的 plan 输出（无对应概念）

---

## 2. 非目标 (Non-goals)

- 不破坏 v2.14-v3.0 API（向后兼容）
- 不引入新必需 npm 依赖
- 不自动执行 `CREATE INDEX`（始终 human-in-loop）
- 不 parse redis / dynamodb 等无 EXPLAIN 概念的 adapter（明确返回 'unsupported'）
- 不做 LLM 自然语言 ↔ EXPLAIN 自解释（v2.17 已提供原始 plan）

## 4. 核心 API

```typescript
// §4.1 — IndexAdvisor
export interface IndexAdvice {
  /** sql segment recommending CREATE INDEX */
  sql: string;
  /** table + column recommendation */
  table: string;
  columns: string[];
  /** estimated improvement: 'low' | 'medium' | 'high' */
  impact: 'low' | 'medium' | 'high';
  /** reason code from heuristic */
  reason: 'seq_scan' | 'large_estimate' | 'no_index_join' | 'sort_no_index';
  /** relevant EXPLAIN row(s) that triggered the advice */
  evidence?: ExplainRow[];
}

export class IndexAdvisor {
  /** Parse EXPLAIN JSON plan output and yield advice. */
  static analyze(plan: ExplainPlan, dbType: string): IndexAdvice[];
}

// §4.2 — PlanDiff
export interface PlanDiffResult {
  identical: boolean;
  added: PlanNode[];
  removed: PlanNode[];
  changed: { node: string; from: ExplainPlan; to: ExplainPlan }[];
  /** Estimated total cost delta (positive = slower, negative = faster). */
  costDelta?: number;
}

export class PlanDiff {
  static compare(planA: ExplainPlan, planB: ExplainPlan): PlanDiffResult;
}

// §4.3 — PlanHistory
export interface PlanHistoryEntry {
  id?: number;
  /** Unique identifier for "the same query" (normalized SQL hash) */
  queryHash: string;
  /** Normalized SQL (stripped of literal values) */
  sqlTemplate: string;
  /** Original SQL when captured */
  sqlOriginal: string;
  /** EXPLAIN result JSON */
  planJson: string;
  /** Adapter that produced the plan */
  dbType: string;
  /** Connection / profile */
  profileName: string | null;
  capturedAt: string;
  durationMs: number;
}

export class PlanHistory {
  async capture(entry: PlanHistoryEntry): Promise<void>;
  async getByHash(queryHash: string): Promise<PlanHistoryEntry[]>;
  async list(limit: number): Promise<PlanHistoryEntry[]>;
}
```

## 7. 数据库迁移 / schema

新建 `plan_history.db`:
```sql
CREATE TABLE IF NOT EXISTS plan_history (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  query_hash TEXT NOT NULL,        -- sha256(normalized SQL)
  sql_template TEXT NOT NULL,      -- normalized SQL
  sql_original TEXT NOT NULL,      -- raw input SQL
  plan_json TEXT NOT NULL,         -- JSON-serialized ExplainResult
  db_type TEXT NOT NULL,
  profile_name TEXT,
  captured_at TEXT NOT NULL,
  duration_ms INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_plan_query_hash ON plan_history(query_hash);
CREATE INDEX IF NOT EXISTS idx_plan_captured_at ON plan_history(captured_at);
```

(v2.17 query_history 不变；plan_history.db 是单独文件，不污染现有 schema.)

## 8. 适配器覆盖

| Adapter | EXPLAIN 行为 | IndexAdvisor | PlanDiff |
|---|---|---|---|
| sqlite | EXPLAIN QUERY PLAN (JSON via SQLite 3.18+) | **native** | native |
| mysql | EXPLAIN FORMAT=JSON / TRADITIONAL | **native** | native |
| postgresql | EXPLAIN (FORMAT JSON) | **native** | native |
| mongodb | `db.collection.find().explain('executionStats')` | **native** (mongo-specific) | native |
| oracle | EXPLAIN PLAN FOR | raw text passthrough | text compare only |
| dameng / kingbase / gaussdb / opengauss / oceanbase / tidb / polardb / vastbase / highgo / goldendb | 同 mysql/pg dialect | **raw passthrough** | text compare |
| mssql | SET SHOWPLAN_TEXT ON | raw passthrough | text compare |
| clickhouse | EXPLAIN AST | raw passthrough | text compare |
| redis | 不适用 | **'unsupported'** | **'unsupported'** |

## 10. 风险与权衡

| 风险 | 等级 | 缓解 |
|---|---|---|
| IndexAdvisor 误报（建议用户创建无用索引） | 高 | 仅对 seq scan / 大 row 估计 / sort + non-index 才建议；显式 `impact` 字段让 LLM 决定 |
| IndexAdvisor 漏报（不推荐关键索引） | 中 | MVP 4 条 heuristic 覆盖 80% 场景；后续 v3.2 加 advanced rules |
| PlanDiff 在 large plan 上慢 | 中 | 限制单 plan < 1000 节点；溢出时返回 partial + warning |
| PlanHistory.db 文件锁 | 低 | 复用 v2.17 multi-backend SQLite + v2.19 cipher 模式 |
| Adapter EXPLAIN 语法差异 | 中 | SQL parser heuristic：每个 adapter 选对应 dialect，`details` 字段返回 raw text 给 LLM |
| MySQL plan cost 解释 | 低 | 总是显示 `cost=X` 字段，LLM 自己判断 |
| lru/retention 给 plan history | 低 | 默认无限大；不加 retention 除非加 env |

**未做（YAGNI）**:
- 跨 profile plan diff
- 自动 apply CREATE INDEX
- LLM 自然语言 EXPLAIN 解读（v2.17 已提供 raw plan）

**回退方案**:
- 所有 17 adapters 都 graceful handle（raw text 或 unsupported），从不抛异常
- PlanHistory 文件路径不存在自动 mkdir
- PlanDiff 大 plan partial + warning 而非 fail
