## Architecture

### Components

| Component | Role | Where |
|---|---|---|
| **Test driver** (Claude Code session) | Drives every MCP tool call, observes response, logs result | Claude Code (this host) |
| **MCP server** | Universal DB MCP, stdio JSON-RPC | `dist/index.js`, started by Claude Code via `.mcp.json` |
| **Container runtime** | One DB at a time, `--restart=always` (no `--rm`) | WSL2 docker |
| **mmx CLI** | Searches Docker Hub + China-region docs for image/env/port | `mmx search "<query>" --region cn` |
| **Bug-fix loop** | When test fails → write bug → assess severity → fix → regression | Claude Code (same session) |

### Data flow

```
[ Claude Code (test driver) ]
   │
   ├─ Bash → wsl docker run --restart=always <image>
   ├─ Bash → mmx search "<db> docker hub" → finds env/port
   ├─ mcp__universal_db_mcp__connect_database → opens single-DB session
   ├─ mcp__universal_db_mcp__<tool>           → exercise (5-step lifecycle)
   └─ Edit   → updates docs/09-reference/e2e-stdio-report.md
       │
       ▼
   [ WSL Ubuntu docker daemon ]
       └─ container e2e-<db>  (--restart=always, persists across sessions)
            │
            ▼
       [ Postgres / MySQL / Redis / ... actual DB ]
```

### Session boundaries

A **session** = one Claude Code runtime with one `.mcp.json` configuration. Sessions end and require Claude Code restart when:
- `.mcp.json` env vars change (env var matrix iterations)
- MCP server crashes (Bug #7 reproduction) — restart + clear state
- DB switches (recommended restart for clean pool state, even though `connect_database` is single-DB)

7 DBs require **7 main sessions** (S1-S7). Adding 7 env var iterations adds up to 7 more (S8-S14). Total: **up to 14 sessions**.

## Test procedure per tool

### Lifecycle for stateful tools (INSERT → UPDATE → SELECT → DELETE → SELECT)

For any tool that has side effects or reads/writes data:

```python
def test_stateful_tool(tool_name, db):
    # 1. INSERT  — create test row
    r1 = invoke(tool_name, action='insert', row={'id': 1, 'val': 'a'})
    assert r1.success == True, "INSERT failed: <error>"

    # 2. UPDATE  — modify test row
    r2 = invoke(tool_name, action='update', row={'id': 1, 'val': 'b'})
    assert r2.success == True

    # 3. SELECT  — verify UPDATE
    r3 = invoke(tool_name, action='select', where={'id': 1})
    assert r3.val == 'b', "UPDATE didn't persist"

    # 4. DELETE  — remove test row
    r4 = invoke(tool_name, action='delete', where={'id': 1})
    assert r4.success == True

    # 5. SELECT  — verify DELETE
    r5 = invoke(tool_name, action='select', where={'id': 1})
    assert r5.row_count == 0, "DELETE didn't remove"
```

For MCP tools that wrap SQL (`execute_query`, `execute_script`, `execute_sql_file`, `execute_batch`), the 5 steps are **direct SQL strings** passed as `sql` param.

For tool-specific tools (`save_template`, `save_profile`, `generate_sample_data`), each step calls the tool with its own args (not raw SQL), and verification reads back via a different tool.

### Lifecycle for read-only tools

```python
def test_readonly_tool(tool_name, db):
    r = invoke(tool_name)
    assert r is not None
    assert 'error' not in r  # or assert known error code if testing failure path
```

### Lifecycle for meta tools

```python
def test_meta_tool(tool_name, db):
    r = invoke(tool_name, action='list')  # or 'schema'
    assert 'expected_key' in r
```

### Common verification helpers

- `assert_no_crash(tool_name)`: tool returns response (not exception), response.jsonrpc.error is null
- `assert_schema_valid(response, schema)`: response matches tool's `inputSchema`/`outputSchema`
- `record_result(tool_name, db, result, status, note)`: append row to report

## Environment variable matrix

Each env var is tested in **default** and **alternative** value within a session. Verifying the env var *affects tool behavior* is the goal.

| Env var | Default | Test alt | What to verify |
|---|---|---|---|
| `DB_LAZY_LOAD_ENABLED` | `true` → **hardcoded `false`** for v5 | `false` (only) | All 43 tools appear in `tools/list` initial response |
| `LOG_LEVEL` | `warn` | `debug` | stderr output volume changes (`debug` produces >2× stderr lines for same call) |
| `DB_ALLOWED_FILE_PATHS` | `/tmp` | `/nonexistent/path` | `execute_sql_file` rejects path outside `/tmp` when set to nonexistent |
| `DB_QUERY_ANALYZER_ENABLED` | `true` | `false` | `explain_query` output differs (analyzer hints present vs absent) |
| `DB_METRICS_ENABLED` | `true` | `false` | `get_metrics` returns empty/degraded when off |
| `DB_PLAN_HISTORY_DB_PATH` | `.e2e-plan-history.db` | `./tmp/plan.db` | plan history file written to specified path |
| `DB_TYPE` | empty | `postgres` | connect_database default type matches env |

Env var matrix is tested in **one extended session per env var** (S8-S14), reusing the same DB setup as S1-S7 baseline.

## DB deploy procedure

For each non-sqlite DB:

```bash
# Step 1: discover docker config
mmx search "<dbname> official docker hub image run command" --region cn
# Example output: postgres:16-alpine, -p 5432:5432, POSTGRES_USER/PASSWORD/DB env

# Step 2: pull image
wsl docker pull <image:tag>

# Step 3: stop old container (if exists)
wsl docker rm -f e2e-<db> 2>/dev/null || true

# Step 4: start new container — CRITICAL: --restart=always, NO --rm
wsl docker run -d --restart=always -p <port>:<port> \
  -e <ENV>=<val> --name e2e-<db> <image:tag>

# Step 5: wait for ready
sleep <n>
wsl docker exec e2e-<db> <healthcheck-cmd>

# Step 6: NEVER delete container during test session — restart=always keeps it alive
```

DBs with non-trivial setup:

| DB | Image | Port | Special env |
|---|---|---|---|
| postgres | `postgres:16-alpine` | 5432 | POSTGRES_USER, POSTGRES_PASSWORD, POSTGRES_DB |
| mysql | `mysql:8` | 3306 | MYSQL_ROOT_PASSWORD, MYSQL_DATABASE |
| redis | `redis:7-alpine` | 6379 | (none — no auth for test) |
| mongodb | `mongo:7` | 27017 | MONGO_INITDB_ROOT_USERNAME, MONGO_INITDB_ROOT_PASSWORD |
| clickhouse | `clickhouse/clickhouse-server:24-alpine` | 8123, 9000 | CLICKHOUSE_DB, CLICKHOUSE_USER, CLICKHOUSE_PASSWORD |
| dm | (China-domestic; `mmx search` `--region cn` for image) | 5236 | SYSDBA_PWD |
| sqlite | (no container — `filePath:':memory:'` or `.e2e-sqlite.db`) | — | — |

## Bug fix loop

When a tool call returns unexpected result:

1. **Record immediately**:
   - Append row to bug log section
   - Add error note to section 3 with exact call + response
2. **Assess severity**:
   - 🔴 **CRITICAL** — blocks >50% of remaining test work in this session → **stop session, fix, restart**
   - 🟡 **MAJOR** — affects 1-2 tools but workaround exists → **continue session, fix in tail**
   - 🟢 **MINOR** — cosmetic or edge case → **log, defer to backlog**
3. **Fix**:
   - For 🟡 in-session: implement fix in same Claude Code session, verify with regression call, then proceed
   - For 🔴 same-session: same as 🟡 but document restart+regression in session log
4. **Regression**:
   - Re-invoke the failing tool + 2-3 related tools in same DB to confirm fix doesn't break neighbors
   - Update bug status from `🔴 OPEN` → `✅ FIXED <commit>`
5. **Document**:
   - Add commit hash to bug log
   - Commit message format: `fix(mcp): Bug #<n> (<short title>)`

### Bug triage decision matrix

| Symptom | Severity | Action |
|---|---|---|
| MCP server crashes (process dies, tool list disappears) | 🔴 CRITICAL | Stop, restart Claude Code, debug, fix before continuing |
| Tool returns wrong data silently | 🔴 CRITICAL | Fix immediately, regress |
| Tool returns clear error for invalid input | ✅ (correct behavior) | No bug |
| Tool errors on valid input but works after retry | 🟡 MAJOR | Log, continue, fix in tail |
| Tool missing from `tools/list` after activation | 🟡 (Bug #8 if Claude Code; OK if not registered) | Document, workaround |
| Tool returns JSON with extra fields not in schema | 🟢 MINOR | Log, defer |
| Tool takes >5s for trivial query | 🟢 MINOR | Log with timing, defer |

## Restart strategy

Triggers that require Claude Code restart + clean .mcp.json load:

1. **Env var change** — edit `.mcp.json`, kill MCP server, restart Claude Code
2. **MCP server crash** — Bug #7 symptom, requires full Claude Code restart
3. **DB switch** — recommended (cleaner state, but technically not required since `connect_database` is single-DB)

Restart protocol:
```
1. /exit Claude Code
2. (User) restart Claude Code
3. Verify .mcp.json loaded correctly (check tool list)
4. Resume testing — connect_database to current DB
```

Between restarts, docker containers persist (--restart=always). State is recoverable.

## Hard constraints (carried from v4, verified)

- **One DB container at a time** — memory-constrained
- **Container `--restart=always` + NO `--rm`** — container death during test = connection loss
- **WSL2** for docker, but Node/npm/MCP run on Claude Code host (Windows)
- **All tests via MCP server** — no raw stdio (same path as real user experience)
- **Bug fixes in same session** via SDD fix-loop (record → assess → fix → regress → document)
- **No silent gaps** — every matrix cell has explicit ✅/❌/⚠️/skip/INFRA
