# Universal DB MCP — v2.17 Query Experience 设计文档

**日期**: 2026-07-24
**作者**: brainstorming 会话
**状态**: 待用户审阅
**范围**: v2.17 P3 — Query Experience（Explain Plan + SQL Lint + 查询历史 + 参数化模板）

---

## 1. 背景与目标

v2.16 完成 Observability（Prometheus `/metrics` + MCP `get_metrics` + 慢查询 ring）后，LLM 已经能"看到"查询的运行时情况。下一步主线是 **Query Experience**——让 LLM 在写 SQL 时能预先看到执行计划，事后能复用历史查询与团队共享的模板。

**4 个能力**:
1. **Explain Plan** — 调各 DB 的 EXPLAIN 拿执行计划，避免 LLM 写慢 SQL
2. **SQL Lint** — 写 SQL 时给 advisory warning（不阻止执行）
3. **查询历史** — 所有 query 持久化，LLM 后续能查过去跑过什么
4. **参数化模板** — 团队共享的 SQL 模板，LLM 调短 id 复用

**配套不做的（推到 v2.18+）**:
- 跨连接 profile 模板（v2.18 Multi-DB 再做）
- 索引建议（需 EXPLAIN + schema 联动）
- Query plan diff
- 历史查询的全文搜索

**配套后续任务**:
- 跑通后写 `docs/query-experience.md`

---

## 2. 非目标 (Non-goals)

- 不破坏现有 API 向后兼容（`execute_query` 响应只增 `lint` 字段）
- 不引入新 npm 依赖（用 v2.16 引入的 SQLite multi-backend: `node:sqlite` + `better-sqlite3`）
- 不重写 `DatabaseService` 核心结构
- 不重写 `safety.ts`（lint 纯 advisory，不替代权限检查）
- 不做 EXPLAIN ANALYZE 真实执行（用户确认读/写都走 EXPLAIN，不真跑）
- 不做模板版本化（每次 save 覆盖）
- 不做模板权限控制（默认全 project 可见）
- 不做历史查询的全文搜索（仅按 db/kind/time 过滤）

---

## 3. 架构总览

核心思路：在 `DatabaseService` 旁路新增 `QueryAnalyzer` 单例，作为 4 个能力的统一入口。它内部维护两个 SQLite connection（templates.db + history.db），复用 v2.16 multi-backend。

```
┌─────────────────────────────────────────────────────────────┐
│                         客户端                                │
│   Claude Desktop (MCP)   /   LLM (MCP)   /   HTTP API        │
└──────────┬───────────────┬────────────────────┬──────────────┘
           │ MCP tool      │ MCP tool          │ HTTP /api/...
           ▼               ▼                    ▼
┌─────────────────────────────────────────────────────────────┐
│              QueryAnalyzer (src/core/query-analyzer.ts)      │
│  ┌─────────────┐ ┌──────────┐ ┌───────────┐ ┌──────────┐   │
│  │ explain(sql)│ │ lint(sql)│ │ getHistory│ │executeTpl│   │
│  └──────┬──────┘ └────┬─────┘ └─────┬─────┘ └─────┬────┘   │
└─────────┼──────────────┼─────────────┼─────────────┼─────────┘
          │              │             │             │
          ▼              ▼             ▼             ▼
   ┌──────────┐   ┌────────────┐  ┌──────────┐  ┌──────────┐
   │ EXPLAIN  │   │ Rule-based │  │ history. │  │templates.│
   │per-DB    │   │ Linter     │  │   db     │  │   db     │
   │adapter   │   │ (regex)    │  │ (SQLite) │  │ (SQLite) │
   └──────────┘   └────────────┘  └──────────┘  └──────────┘
```

**关键决策**:
1. `QueryAnalyzer` 是 DatabaseService 的可选旁路（`setQueryAnalyzer()`），不强制依赖
2. 两个 SQLite db 默认在 `${cwd}/.db-mcp/` 下，env var 可覆盖
3. 模板和 history 完全独立 schema，事务隔离
4. `execute_query` 现有路径**不动**——lint 不阻止执行，只是 advisory 返回
5. MCP tool description 全部 < 100 字符（控制 token）

## 4. 核心组件 API

`src/core/query-analyzer.ts` 暴露 4 个方法组：

```typescript
export interface QueryAnalyzerOptions {
  templatesDbPath: string;
  historyDbPath: string;
  historyTtlDays: number;
  enabled: boolean;
  maxHistoryRows: number;
  explainTimeoutMs: number;
}

export class QueryAnalyzer {
  constructor(options: QueryAnalyzerOptions);

  // Explain Plan
  async explain(sql: string, params?: unknown[]): Promise<ExplainResult>;

  // SQL Lint (pure rules, sync)
  lint(sql: string): LintResult;

  // 查询历史
  async getHistory(filter?: HistoryFilter): Promise<QueryHistoryEntry[]>;
  async recordQuery(entry: QueryHistoryInput): Promise<void>;

  // 模板管理
  async saveTemplate(input: TemplateInput): Promise<Template>;
  async listTemplates(filter?: { tag?: string }): Promise<Template[]>;
  async getTemplate(id: string): Promise<Template | null>;
  async deleteTemplate(id: string): Promise<void>;
  async executeTemplate(id: string, params: Record<string, unknown>): Promise<QueryResult>;
}

// Explain
export interface ExplainResult {
  db: string;
  sql: string;
  plan: ExplainRow[];
  raw: string;
  format: 'tabular' | 'xml' | 'json' | 'text';
  duration_ms: number;
}

export interface ExplainRow {
  id?: number;
  select_type?: string;
  table?: string;
  type?: string;
  possible_keys?: string;
  key?: string;
  key_len?: string;
  ref?: string;
  rows?: number;
  Extra?: string;
  operation?: string;
  object_name?: string;
  cost?: number;
}

// Lint
export type LintSeverity = 'error' | 'warning' | 'info';
export interface LintIssue {
  rule: string;
  severity: LintSeverity;
  line?: number;
  message: string;
  suggestion?: string;
}
export interface LintResult {
  sql: string;
  issues: LintIssue[];
  hasErrors: boolean;
  hasWarnings: boolean;
}

// History
export interface QueryHistoryEntry {
  id: number;
  ts: string;
  db: string;
  kind: string;
  sql: string;
  params: string | null;
  duration_ms: number;
  rows: number | null;
  error: string | null;
  error_code: string | null;
}
export interface HistoryFilter {
  db?: string;
  kind?: string;
  since?: string;
  until?: string;
  limit?: number;
  onlyErrors?: boolean;
}

// Template
export interface Template {
  id: string;
  name: string;
  description: string;
  sql: string;
  parameters: TemplateParam[];
  tags: string[];
  created_at: string;
  updated_at: string;
  created_by: string;
  use_count: number;
}
export interface TemplateParam {
  name: string;
  type: 'string' | 'number' | 'boolean' | 'date' | 'sql_identifier';
  required: boolean;
  default?: unknown;
  description?: string;
}
export interface TemplateInput {
  name: string;
  description: string;
  sql: string;
  parameters: Omit<TemplateParam, 'name'>[];
  tags?: string[];
}
```

**关键设计点**:
- `QueryAnalyzer` 单例（`export const queryAnalyzer = new QueryAnalyzer(...)`）
- SQLite connection lazy open：第一次 `getHistory` 时才打开
- 模板参数类型限定 5 种（`sql_identifier` 用 v2.15.0 的 `validateIdentifier` 白名单防注入）
- 查询历史硬上限 10000 行，配 TTL 30 天双重保险
- WAL 模式 (`PRAGMA journal_mode=WAL`) 支持并发读

## 5. 集成点

**4 类埋点位置**（在 `DatabaseService`）:

| # | 位置 | 调用 | 备注 |
|---|------|------|------|
| 1 | `executeQuery` 入口 | `queryAnalyzer?.recordQuery({...})` | 写 history.db (async fire-and-forget) |
| 2 | `executeScript` 入口 | 同上 (kind='script') | |
| 3 | `executeBatch` 入口 | 同上 (kind='batch') | |
| 4 | `executeQuery` / `executeScript` / `executeBatch` 响应 | 增 `lint: LintResult` 字段 (advisory) | LLM 看到后可改写 SQL |

**recordQuery 时机**（fire-and-forget）:
```typescript
this.queryAnalyzer?.recordQuery({
  ts: new Date().toISOString(),
  db: this.config.type,
  kind,
  sql: query,
  params: params ? JSON.stringify(params) : null,
  duration_ms: elapsed,
  rows: result.rows?.length ?? null,
  error: null,
  error_code: null,
}).catch(err => console.error('[queryAnalyzer] recordQuery failed:', err));
```

**关键不动**:
- 不动 `safety.ts` (lint 纯 advisory)
- 不动 v2.16 metrics 路径
- 不强制 lint（关闭 analyzer 时跳过）

**SQL 截断**: history 存 SQL 限 4KB（与 v2.16 慢查询 ring 一致）

## 7. 配置与环境变量

新增 6 个 env var，全部 optional:

| Env var | 默认 | 作用 |
|---------|------|------|
| `DB_QUERY_ANALYZER_ENABLED` | `true` | 全局开关（false 时 QueryAnalyzer 全部 no-op） |
| `DB_TEMPLATES_DB_PATH` | `${cwd}/.db-mcp/templates.db` | 模板 SQLite 文件路径 |
| `DB_HISTORY_DB_PATH` | `${cwd}/.db-mcp/history.db` | 历史 SQLite 文件路径 |
| `DB_HISTORY_TTL_DAYS` | `30` | 历史过期天数 |
| `DB_HISTORY_MAX_ROWS` | `10000` | 硬上限行数 |
| `DB_EXPLAIN_TIMEOUT_MS` | `10000` | EXPLAIN 超时 |

**集成到 config 体系**:
- `AppConfig.queryAnalyzer: { enabled, templatesDbPath, historyDbPath, historyTtlDays, historyMaxRows, explainTimeoutMs }`
- 沿用 v2.16 模式（顶层，不嵌 http）

**TTL 实现**:
- 启动时跑 cleanup: `DELETE FROM history WHERE ts < datetime('now', '-N days')`
- 写新 entry 前如果 count >= maxRows, 删除最旧 10%（避免每次 DELETE 抖动）

**配置校验**:
- `historyTtlDays` 必须正整数，错误 warn + 30
- `historyMaxRows` 必须正整数，错误 warn + 10000
- `DB_QUERY_ANALYZER_ENABLED` 接受 true/false/1/0/yes/no

**与 .gitignore 关系**:
- 仓库根 `.gitignore` 加 `.db-mcp/` (用户可选)
- README 提示：模板想团队共享就 commit templates.db，history 永远别 commit

## 8. Lint 规则

| Rule | 严重 | 触发 |
|------|------|------|
| `select-star` | warning | `SELECT *` |
| `no-where-update` | error | `UPDATE/DELETE` 无 WHERE |
| `no-limit-update` | warning | `UPDATE/DELETE` 无 LIMIT |
| `in-thousand` | warning | `IN (?,?,...)` > 1000 项 |
| `leading-wildcard-like` | warning | `LIKE '%xxx%'` |
| `distinct-without-index-hint` | info | `SELECT DISTINCT` |
| `unqualified-table` | info | 无 schema 前缀的表 |
| `union-vs-union-all` | info | `UNION` 不带 `ALL` |
| `order-by-no-limit` | info | `ORDER BY` 无 LIMIT |
| `double-quoted-identifier` | warning | ANSI 模式用 `"` 引列 |

实现：`src/utils/sql-linter.ts`，纯规则引擎，sync，无 IO。每条规则一个函数，返回 `LintIssue | null`。

```sql
CREATE TABLE templates (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL UNIQUE,
  description TEXT,
  sql TEXT NOT NULL,

```

```sql
CREATE TABLE query_history (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  ts TEXT NOT NULL,
  db TEXT NOT NULL,
  kind TEXT NOT NULL,
  sql TEXT NOT NULL,
  params TEXT,
  duration_ms INTEGER NOT NULL,
  rows INTEGER,
  error TEXT,
  error_code TEXT
);
CREATE INDEX idx_history_ts ON query_history(ts);
CREATE INDEX idx_history_db ON query_history(db, kind);
```

## 11. 风险与权衡

| 风险 | 等级 | 缓解 |
|------|------|------|
| EXPLAIN 拿不到 plan（方言差异大） | 高 | 保留 `raw` 字段原样返回；`plan` 尽力解析为 `ExplainRow[]`，失败时 `plan=[]` |
| 历史 SQLite 写并发 | 中 | WAL 模式（`PRAGMA journal_mode=WAL`）；单 process 单 writer |
| 模板参数 SQL 注入 | 高 | `${param}` 占位符仅替换文本；`sql_identifier` 类型用 `validateIdentifier` 白名单 |
| history.db 磁盘爆 | 中 | `maxRows` 硬上限 + TTL + 启动清理 + 写前 LRU 淘汰 |
| templates.db 并发写 | 低 | 单 process 串行化；模板数量小（几百条） |
| Lint 误报 | 中 | 规则保守，只标记高置信问题；不阻断执行 |
| EXPLAIN 慢 | 中 | 10s 默认超时，env 可配 |
| DatabaseService 改 4 处埋点 | 低 | recordQuery 走 fire-and-forget catch，query 路径不受影响 |
| Explain per-adapter 抽象 | 中 | v2.17 优先 4 大主流（MySQL/PostgreSQL/SQLite/SQL Server），其他返回 raw |
| 模板导入/导出 | 低 | v2.17 不做；团队通过 commit `.db-mcp/templates.db` 共享；v2.18 再加 YAML |

**未做 (YAGNI)**:
- 模板版本化 / 权限控制 / 跨 profile / dry-run
- EXPLAIN ANALYZE 真实执行
- 索引建议
- Query plan diff
- 历史查询的全文搜索

**回退方案**:
- `DB_QUERY_ANALYZER_ENABLED=false` 一键全关
- QueryAnalyzer 构造失败不阻断服务（warn + 标记 disabled）
- 历史 SQLite 损坏时 fallback 到内存 ring（与 v2.16 一致）
