**日期**: 2026-07-24
**作者**: brainstorming 会话
**状态**: ✅ 用户批准所有 11 节
**范围**: v2.20 P3 — Profile 加密完整兑现 + Profile 共享 + Key rotation + History 全文搜索

---

## 1. 背景与目标

v2.18 + v2.19 完成 **Multi-DB + Profile 加密（仅 profiles.db）+ 跨 profile 模板/历史**。仍欠 4 类已被 spec 反复推后的能力，每次都延后但从未兑现：

1. **SQLCipher 加密 templates.db / history.db** — v2.19 已把 `DB_TEMPLATES_DB_KEY` / `DB_HISTORY_DB_KEY` 加为 env **占位**，但代码侧**没接**，文档与实现不一致。
2. **Profile YAML/JSON 导入导出** — v2.18 推后；profiles.db 因含密码不能像 templates.db 那样 commit 共享，YAML/JSON 才能走 PR / Vault。
3. **Key rotation（多 key 支持）** — v2.19 §11 明文承诺"v2.20+ 做"；现在用户想轮换 profile 密码只能删 db 重来。
4. **History FTS5 全文搜索** — v2.17 §2 + v2.19 §11 都推后；LLM 实际用时会找"上周那次模糊 LIKE xxx 的查询"，SQLite FTS5 零依赖内置。

**4 个能力**:
1. `templates.db` + `history.db` 支持 SQLCipher 加密（兑现 v2.19 占位）
2. Profile YAML/JSON export + import（可选 redact secrets）
3. Key rotation（3 个加密 DB 都支持）
4. History FTS5 全文索引（init 自动 backfill）

**配套不做的（推到 v2.21+ / v3.x）**:
- 跨 profile JOIN / 事务 (XA)
- 索引建议 / Query plan diff
- 读副本延迟自动检测
- OS keyring 集成
- Profile 模板版本控制

---

## 2. 非目标 (Non-goals)

- 不引入新 npm 必需依赖（仍用 v2.19 的 `better-sqlite3-multiple-ciphers`，YAML 用 SQLite 的 FTS5 + 内置字符串处理即可，**0 新 dep**）
- 不破坏 v2.14-v2.19 API（向后兼容 + 自动 migration）
- 不做 profile 双向同步（只 export → import，不做 conflict resolution）
- 不做 key rotation 的 CLI 工具链（用 MCP tool + HTTP endpoint 即可，CLI 后续 v2.21 加）
- 不做 OS keyring 集成
- 不做 profile import 的"重命名/合并"高级模式（只支持 merge/replace 两态）

## 3. 架构总览

```
┌────────────────────────────────────────────────────────────────┐
│  Stores (Profile / Template / History)                          │
│  constructor(dbPath, options?: { cipherKey?: string })           │
│  init() → 选 backend (Native vs Cipher via detectEncrypted)     │
│  rotateKey?(newKey)  ← v2.20 NEW                                │
└─────────┬──────────────────────────────┬──────────────────────┘
          │                              │
          ▼                              ▼
┌─────────────────────┐         ┌─────────────────────────────────┐
│   Native backend    │         │   Cipher backend (SQLCipher)    │
└─────────────────────┘         └─────────────────────────────────┘

Profile YAML serializer (v2.20 NEW):
  export(includeSecrets=false) → YAML / JSON string
  parse(input, opts={mode: 'merge' | 'replace', dryRun?: boolean}) → {ok, errors[]}
  redaction: db.password = 'REDACTED' unless includeSecrets

HistoryStore FTS5 (v2.20 NEW):
  init() → CREATE VIRTUAL TABLE history_fts USING fts5(sql, content='query_history', content_rowid='id')
  triggers: AFTER INSERT/DELETE on query_history → sync history_fts
  init() backfill: INSERT OR IGNORE INTO history_fts(rowid, sql) SELECT id, sql FROM query_history
  query() adds 'q' param: WHERE rowid IN (SELECT rowid FROM history_fts WHERE history_fts MATCH ?)

KeyRotator (v2.20 NEW):
  rotate(dbPath, oldKey?, newKey) — read all with oldKey/open → re-init with newKey → write all
  原子替换: 临时 .rotating.tmp 写完再 rename() 替换
  失败保留旧 DB（不删）+ 错误堆栈
```

## 6. 配置与环境变量

| Env var | 默认 | 作用 |
|---|---|---|
| `DB_PROFILE_ENCRYPTION_KEY` | 空 | v2.19 profile 加密（保留） |
| `DB_PROFILE_ENCRYPTION_KEY_OLD` | 空 | v2.20 新增：rotation 期间允许 old/new key 同时打开 |
| `DB_TEMPLATES_DB_KEY` | 空 | **v2.19 占位兑现**：templates.db SQLCipher |
| `DB_TEMPLATES_DB_KEY_OLD` | 空 | templates rotation old key |
| `DB_HISTORY_DB_KEY` | 空 | **v2.19 占位兑现**：history.db SQLCipher |
| `DB_HISTORY_DB_KEY_OLD` | 空 | history rotation old key |

**Rotation 行为**:
- 启动时若 `*_KEY_OLD` 设置：尝试用 old key 打开 → `PRAGMA cipher_version` 验证成功 → 读所有 rows → 用 new key 写新文件 → rename 原子替换 → 清掉 `*_KEY_OLD` env （warn 用户）
- 启动时若 `*_KEY_OLD` 未设置：普通路径（直接 new key 打开）
- 启动时若 `*_KEY_OLD` 设置但 cipher_version 不匹配：报清晰错，不静默 fallback

**显式 rotation**（CLI / MCP）：
- `rotate_profile_key({profileName, oldKey, newKey})`（如 ProfileManager 单独加密 profiles.db，不需要 profileName）
- 失败时保留原 db（写 `.rotating.failed` 临时文件），不删
- 启动日志写「rotated profiles.db: N profiles」

## 7. 数据库迁移

### 7.1 `templates.db` (v2.19 → v2.20)

SQLCipher 是文件级加密，不影响 SQLite 内部 schema。v2.20 不加 SQL 列；只是 `init()` 走 cipher backend（如果 `cipherKey` 配置）。

```sql
-- v2.19 已加（幂等）：
ALTER TABLE templates ADD COLUMN profile_name TEXT;
-- v2.20 无 schema 改动
```

### 7.2 `history.db` (v2.19 → v2.20)

```sql
-- v2.19 已加（幂等）：
ALTER TABLE query_history ADD COLUMN profile_name TEXT;

-- v2.20 新增 FTS5 + triggers (幂等 CREATE IF NOT EXISTS)：
CREATE VIRTUAL TABLE IF NOT EXISTS history_fts USING fts5(
  sql, content='query_history', content_rowid='id'
);
CREATE TRIGGER IF NOT EXISTS trg_history_ai AFTER INSERT ON query_history BEGIN
  INSERT INTO history_fts(rowid, sql) VALUES (new.id, new.sql);
END;
CREATE TRIGGER IF NOT EXISTS trg_history_ad AFTER DELETE ON query_history BEGIN
  INSERT INTO history_fts(history_fts, rowid, sql) VALUES ('delete', old.id, old.sql);
END;
CREATE TRIGGER IF NOT EXISTS trg_history_au AFTER UPDATE ON query_history BEGIN
  INSERT INTO history_fts(history_fts, rowid, sql) VALUES ('delete', old.id, old.sql);
  INSERT INTO history_fts(rowid, sql) VALUES (new.id, new.sql);
END;

-- init() backfill (一次，与 cipherBackend 无关)：
INSERT OR IGNORE INTO history_fts(rowid, sql) SELECT id, sql FROM query_history;
```

### 7.3 `profiles.db` (v2.19 → v2.20)

SQLCipher 加密已在 v2.19 完成；v2.20 不加新 schema 列；rotation 改的是文件级加密 key（rename-替换）。

## 9. 风险与权衡

| 风险 | 等级 | 缓解 |
|---|---|---|
| FTS5 在加密 DB 中 trigger 回写失败 | 中 | trigger 在 transparent cipher 层下工作（SQLCipher 文档支持）；测试覆盖 ALTER/INSERT/DELETE/UPDATE 4 个 DML |
| Rotation 中途断电 / 进程 kill → 数据半写状态 | 高 | 每个 DB 用临时 `.rotating.tmp` 写完再 `rename()` 原子替换；轮换 single-DB，不跨 DB 写 |
| YAML import 把别人提交的有害 profile（如 `type: sqlite` 但带 `allowWrite: false`）灌进来 | 中 | `validate()` 拒绝未知 type；`role` 白名单 (primary/replica/analytics)；`enabled` import 后默认 false |
| FTS5 sync trigger 性能（每条 query_history 都触发） | 低 | trigger 代价 < 10μs；historyMaxRows LRU 已控写入量 |
| Redact 后用户丢失密码无法 reconnect | 低 | 文案明确要求"export with --include-secrets 或重新输入 password" |
| 3 个 DB 都需要 cipher dep 才能完整用 | 低 | 沿用 v2.19 现状（optionalDependencies），不强制安装 |
| YAML 解析使用 SQLite 内置 + 手写 vs 引入 `js-yaml` | 低 | v2.20 选择**手写 minimal YAML parser**（只支持 string/int/bool/array/object），避免新依赖；YAML v1.2 子集够用 |
| Rotation 时 cipher_version 不匹配 | 中 | 抛清晰错 `failed to decrypt profiles.db with old key — cannot rotate`；保留原 db 不动 |

**未做（YAGNI）**:
- CLI tool（`rotate-profile-key`） — 通过 MCP `rotate_profile_key` tool + HTTP endpoint 已可操作，CLI 增加 operating 风险
- Profile YAML diff 工具 — 留给 v2.21+
- 嵌入式 KMS 集成 — 留给 v3.x

**回退方案**:
- 所有 3 个 store cipherKey 都可独立留空 → plaintext fallback + warn 一次
- YAML parser 只读 v1 子集，v2 YAML 视为 reject
- Rotation 失败保留原 db + `.rotating.failed` 文件供修复
