# Universal DB MCP — v2.18 Multi-DB 设计文档

**日期**: 2026-07-24
**作者**: brainstorming 会话
**状态**: 待用户审阅
**范围**: v2.18 P3 — Multi-DB 多库管理（多 profile + 运行时切换 + 连接分组 + 全局视图）

---

## 1. 背景与目标

v2.14 引入了"零配置启动 / 无连接模式"和 `connect_database` 工具让 LLM 动态连库；v2.16 加了可观测性；v2.17 加了 query experience 4 能力（Explain / Lint / History / Template）。但一个 server 进程仍只连**一个**库。下一步主线是 **Multi-DB** — 一个进程同时管多个库的 profile，运行时切换，读/写路由，全局 schema 视图。

**4 个能力**:
1. **多 profile 管理** — save/list/get/delete profile 定义，持久化到 SQLite
2. **运行时切换** — `use_profile(name)` 一行切到任意已配置 profile
3. **连接分组** — profile.role = `primary` / `replica` / `analytics`，读 round-robin 走 replica
4. **全局视图** — `get_global_schema` 并行查所有 enabled profile 的 schema 合并

**配套不做的（推到 v2.19+）**:
- Profile 加密 (SQLCipher)
- 跨 profile 模板 / 历史
- 跨 profile JOIN / 跨 profile 事务
- Profile 导入/导出 (YAML/JSON)

**配套后续任务**:
- 跑通后写 `docs/multi-db.md`

---

## 2. 非目标 (Non-goals)

- 不破坏现有 API 向后兼容（`connect_database` 保留, `use_profile` 是新增）
- 不引入新 npm 依赖
- 不重写 `ConnectionManager`（扩展而非重写）
- 不重写 `DatabaseService`（profile 切换在 ConnectionManager 层）
- 不做 profile 密码加密 (v2.19+ SQLCipher)
- 不做跨 profile JOIN
- 不做跨 profile 事务 (XA / 2PC)
- 不做读副本延迟自动检测
- 不做 profile 导入/导出

---

## 3. 架构总览

核心思路：在 `ConnectionManager` 上面加一个 `ProfileManager` 抽象层。`ProfileStore` 持久化 profile 定义（SQLite），`ConnectionManager` 加 `liveProfiles: Map<name, LiveProfile>` 字段管理运行时连接。HTTP 模式继续用 sessionId；MCP 模式用 profile name。

```
┌─────────────────────────────────────────────────────────────────┐
│                         客户端                                    │
│   Claude Desktop (MCP)   /   HTTP API (multi-session)             │
└──────────┬──────────────────────────┬────────────────────────────┘
           │                          │
           │ use_profile(name)        │ /api/profiles (CRUD)
           │ list_profiles()          │ /api/profiles/:name/connect
           ▼                          ▼
┌─────────────────────────────────────────────────────────────────┐
│                  ProfileManager (新)                             │
│  ┌──────────────────┐ ┌──────────────────┐ ┌──────────────────┐ │
│  │  ProfileStore    │ │ ConnectionManager│ │ GlobalSchemaView │ │
│  │  (SQLite)        │ │ (扩展 profiles   │ │ (parallel fetch  │ │
│  │                  │ │  map + session)  │ │ + SchemaEnhance) │ │
│  └──────────────────┘ └──────────────────┘ └──────────────────┘ │
└──────────┬─────────────────┬──────────────────┬───────────────────┘
           │                 │                  │
           ▼                 ▼                  ▼
   ┌──────────────┐  ┌──────────────┐  ┌──────────────────┐
   │ profiles.db  │  │ mysql pool   │  │ SchemaEnhancer  │
   │ (SQLite)     │  │ pg pool      │  │ (v2.8 reuse)     │
   │              │  │ oracle pool  │  │                  │
   └──────────────┘  └──────────────┘  └──────────────────┘
```

**关键决策**:
1. ProfileStore 复用 v2.16 multi-backend SQLite（`profiles.db`）
2. HTTP 模式不破坏：sessionId 继续工作，session 内部可指定 profile name
3. `use_profile` 是 MCP 新工具，`connect_database` 保留作为 fallback（动态建连）
4. 读 / 写路由在 `QueryRouter`（小模块，~50 行）
5. 全局 schema 用 `Promise.all` 并行查多个 profile 的 schema，max 50 并行

## 4. 核心组件 API

```typescript
// Profile 定义
export interface Profile {
  id: string;                  // 8 字符 nanoid
  name: string;                // 唯一 human-readable
  description: string;
  type: DbType;
  config: DbConfig;
  role: 'primary' | 'replica' | 'analytics';
  tags: string[];
  enabled: boolean;
  created_at: string;
  updated_at: string;
  created_by: string;
  use_count: number;
}
export interface ProfileInput {
  name: string;
  description: string;
  type: DbType;
  config: DbConfig;
  role?: 'primary' | 'replica' | 'analytics';
  tags?: string[];
  enabled?: boolean;
}

// ProfileStore
export class ProfileStore {
  constructor(dbPath: string);
  async save(input: ProfileInput, createdBy?: string): Promise<Profile>;
  async list(filter?: { role?: string, tag?: string, enabled?: boolean }): Promise<Profile[]>;
  async get(name: string): Promise<Profile | null>;
  async delete(name: string): Promise<boolean>;
  async incrementUseCount(name: string): Promise<void>;
  async setEnabled(name: string, enabled: boolean): Promise<void>;
  async close(): Promise<void>;
}

// LiveProfile
export interface LiveProfile {
  profile: Profile;
  adapter: DbAdapter;
  service: DatabaseService;
  pool: Pool;
  connectedAt: Date;
}

// ProfileManager
export class ProfileManager {
  constructor(opts: ProfileManagerOptions);
  async saveProfile(input: ProfileInput): Promise<Profile>;
  async listProfiles(filter?: {role?, tag?, enabled?}): Promise<Profile[]>;
  async getProfile(name: string): Promise<Profile | null>;
  async deleteProfile(name: string): Promise<boolean>;
  async loadProfile(name: string): Promise<LiveProfile>;
  async unloadProfile(name: string): Promise<void>;
  async getLive(name: string): Promise<LiveProfile | null>;
  async listLive(): Promise<LiveProfile[]>;
  async routeQuery(profile: Profile, sql: string, kind: 'read' | 'write', params?: unknown[]): Promise<QueryResult>;
  async getGlobalSchema(): Promise<GlobalSchemaView>;
  async closeAll(): Promise<void>;
}

export interface ProfileManagerOptions {
  enabled: boolean;
  profilesDbPath: string;
  maxProfiles: number;
  cacheConfig?: Partial<SchemaCacheConfig>;
}

export interface GlobalSchemaView {
  generatedAt: string;
  profiles: Array<{
    name: string;
    type: string;
    role: string;
    tables: Array<{
      schema: string;
      name: string;
      columns: Array<{ name: string; type: string; nullable: boolean; comment?: string }>;
      primaryKey: string[];
      foreignKeys: ForeignKeyInfo[];
      indexes: IndexInfo[];
      comment?: string;
    }>;
  }>;
}
```

**关键设计点**:
- `Profile` 唯一 name（不是 id），LLM 用 `use_profile("prod-mysql")` 直观
- `config` 字段存完整 DbConfig（含密码），README 强提示 `.gitignore`
- `LiveProfile` 是 profile + adapter 运行时实例
- `routeQuery` 根据 `kind='read'/'write'` 选 primary / replica，read 走 round-robin
- `getGlobalSchema` 用 `Promise.all` 并行查所有 enabled profile 的 schema

**路由算法 (routeQuery)**:
```typescript
if (kind === 'write' || profile.role === 'primary') {
  return live.adapter.executeQuery(sql, params);  // primary 走 profile 自己
} else {
  // kind === 'read' && role === 'replica' 或 'analytics': round-robin 同 role group
  const peers = [...liveProfiles.values()].filter(lp => lp.profile.role === profile.role);
  const pick = peers[roundRobinCounter++ % peers.length];
  return pick.adapter.executeQuery(sql, params);
}
```

## 5. 集成点

| # | 位置 | 调用 | 备注 |
|---|------|------|------|
| 1 | `ConnectionManager` 内部 | 扩展加 `liveProfiles` 字段 | 现有 session 不动 |
| 2 | `DatabaseMCPServer` 构造 | 接收 `ProfileManager` 实例 (optional) | 跟 v2.17 `queryAnalyzer` 模式一样 |
| 3 | MCP `use_profile` tool | `profileManager.loadProfile(name)` + 设 `this.activeProfile` | 取代 connect_database 的 role |
| 4 | MCP `connect_database` (已有) | 保留，加 `profileName` optional | 显式 save profile 后再 connect |
| 5 | MCP `get_schema` | 改用 `activeProfile` 而非 `this.config` | 自动用当前 active profile |
| 6 | MCP `get_global_schema` 新增 | `profileManager.getGlobalSchema()` | 4 能力之一 |
| 7 | HTTP `/api/profiles/*` 路由 | CRUD + connect | 8 个新端点 |
| 8 | HTTP `POST /api/query` | 加 `profileName` query/body 参数 | 选 profile 跑 query |
| 9 | DatabaseService 构造 | 不动，profile 切换在 ConnectionManager 层 | 保持单一 source of truth |

**HTTP `/api/profiles/*` 端点**:
| 端点 | 方法 | 说明 |
|------|------|------|
| `/api/profiles` | GET | list (filter by role/tag/enabled) |
| `/api/profiles` | POST | save (ProfileInput body) |
| `/api/profiles/:name` | GET | get |
| `/api/profiles/:name` | DELETE | delete + unload |
| `/api/profiles/:name/enable` | POST | setEnabled(true) |
| `/api/profiles/:name/disable` | POST | setEnabled(false) |
| `/api/profiles/:name/connect` | POST | loadProfile |
| `/api/profiles/:name/disconnect` | POST | unloadProfile |
| `/api/global-schema` | GET | 全局视图 |

**Session 与 profile 关系 (HTTP)**:
- session 默认绑一个 profile (创建时指定或第一个 load 的 profile)
- session 内可切到其他 profile (request body 传 `profileName`)
- 多个 session 可共享同一 profile (LiveProfile 是连接池, sessionId 是用户身份)

**get_metrics 扩展**:
- 增 `multi_db` category 返回 `{ active_profile, live_profiles, total_profiles }`

## 6. 配置与环境变量

新增 5 个 env var：

| Env var | 默认 | 作用 |
|---------|------|------|
| `DB_MULTI_DB_ENABLED` | `true` | 全局开关 (false 时 ProfileManager no-op) |
| `DB_PROFILES_DB_PATH` | `${cwd}/.db-mcp/profiles.db` | profile 持久化 SQLite 路径 |
| `DB_PROFILES_MAX` | `50` | profile 数量硬上限 (LRU 卸载最旧 live) |
| `DB_DEFAULT_PROFILE_ROLE` | `primary` | 新 save profile 时 default role |
| `DB_READ_ROUTING` | `round-robin` | 读路由策略: `round-robin` / `random` / `least-loaded` |

**集成到 config 体系**:
- `AppConfig.profileManager: { enabled, profilesDbPath, maxProfiles, defaultRole, readRouting }`

**配置校验**:
- `maxProfiles` 正整数，错误 warn + 50
- `defaultRole` ∈ `primary|replica|analytics`，错误 warn + `primary`
- `readRouting` ∈ `round-robin|random|least-loaded`，错误 warn + `round-robin`
- `DB_MULTI_DB_ENABLED` 接受 true/false/1/0/yes/no

**与 .gitignore 关系**:
- `.db-mcp/profiles.db` 含密码 — **永远不 commit**
- README 提示: profiles.db 加 .gitignore

**与 v2.14/v2.16/v2.17 兼容**:
- `DB_MULTI_DB_ENABLED=false` 完全退回 v2.14 单库模式
- 现有 `connect_database` 工具仍可用

## 7. 数据库 Schema

`profiles.db`:
```sql
CREATE TABLE profiles (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL UNIQUE,
  description TEXT,
  type TEXT NOT NULL,
  config_json TEXT NOT NULL,
  role TEXT NOT NULL DEFAULT 'primary',
  tags_json TEXT NOT NULL DEFAULT '[]',
  enabled INTEGER NOT NULL DEFAULT 1,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  created_by TEXT NOT NULL,
  use_count INTEGER DEFAULT 0
);
CREATE INDEX idx_profiles_name ON profiles(name);
CREATE INDEX idx_profiles_role ON profiles(role);
CREATE INDEX idx_profiles_tags ON profiles(tags_json);
```

**配置 password 序列化**:
- v2.18 暂不加密，明文存 SQLite (config_json 字段)
- README 强提示 `.gitignore`
- v2.19+ 改 SQLCipher

- getGlobalSchema 缓存: 第二次调比第一次快

## 9. 风险与权衡

| 风险 | 等级 | 缓解 |
|------|------|------|
| profiles.db 含明文密码 | 高 | README 强提示 `.gitignore`；v2.19+ 加 SQLCipher |
| 50 profile × 17 adapter 启动 OOM | 中 | 启动时按 `enabled=true` lazy load；超 maxProfiles 时 LRU 卸载最旧 live |
| Round-robin 读路由: replica 延迟不均 | 低 | v2.18 round-robin 简单；v2.19+ 加 `least-loaded` |
| get_global_schema 慢: 50 profile 并行查 schema | 中 | 复用 v2.1 schema 缓存 (5 分钟 TTL)；Promise.all 并行；每 profile 加 3s timeout |
| use_profile 误用 (LLM 切到 prod) | 中 | MCP tool description 强提示 read/write 区分 |
| connect_database 兼容代码路径分支多 | 低 | 旧路径保持原样，新加 `profileName` optional |
| profile 名字冲突 (LLM 拼错) | 中 | save_profile 严格校验；list_profiles 返回所有避免拼错 |
| HTTP session 与 profile 状态不一致 | 低 | session.bindProfile(name) 时校验 profile 存在 |
| DatabaseService schema 缓存键冲突 | 中 | per-DatabaseService 实例，缓存天然隔离 |
| 切换 profile 时 in-flight query 中断 | 低 | liveProfiles 是 pool 复用，切换只换 activeProfile 引用 |

**未做 (YAGNI)**:
- Profile 加密 (SQLCipher) — v2.19+
- 跨 profile JOIN / 跨 profile 事务 (XA) — v3.x
- 跨 profile 模板 / 历史 — v2.19+
- 读写分离权重（5:5 vs 7:3）— 简单 round-robin 够用
- Profile 导入/导出 — v2.19+
- Read replica 延迟自动检测
- Connection 复用 (HikariCP-style 共享)

**回退方案**:
- `DB_MULTI_DB_ENABLED=false` 完全单库模式
- profile save 失败不阻断 startup
- use_profile 失败抛清楚错误，LLM 可改用 connect_database fallback
- profiles.db 损坏时 fallback 到内存 profile map
